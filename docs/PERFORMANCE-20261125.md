# اصلاح بارگذاری صفحهٔ اصلی — ۲۵ نوامبر ۲۰۲۶

این تغییر بر اساس متن گزارش ارسالی است؛ فایل‌های اصلی mobile.json و desktop.json
در ورودی موجود نبودند. اعداد گزارش، نتیجهٔ اندازه‌گیری این نسخه نیستند.

## تغییرات

- فایل صفحه و CSS آن از manifest فعلی Vite در head بارگذاری می‌شوند. بنابراین
  دریافت Home منتظر اجرای app نمی‌ماند و هش فایل در کد ثابت نشده است.
- تصویر هیرو با اولویت بالا و سه media query مطابق Home.vue پیش‌بارگذاری می‌شود.
  تنظیمات تصویر موبایل، تبلت، دسکتاپ و تصویر بخش hero همان ترتیب اولویت Vue را دارند.
- پیش‌دریافت خودکار همهٔ صفحات حذف شده است. روی دستگاه با pointer: coarse،
  GSAP/ScrollTrigger دریافت نمی‌شود؛ روی دسکتاپ بعد از load و فرصت idle اجرا می‌شود.
  محتوای داخل دید کاربر هنگام شروع دیرهنگام انیمیشن مخفی نمی‌شود.
- حلقهٔ انیمیشن مشتریان و نظرات بیرون از viewport و در تب مخفی متوقف می‌شود.
- در صورت تنظیم هر دو شناسه، GTM مسئول GA4 است. تگ مستقیم GA4 فقط در نبود GTM
  ساخته می‌شود. بارگذاری پس از اولین تعامل یا سه ثانیه پس از load انجام می‌شود و
  با تعامل‌های مکرر تکرار نمی‌شود. GTM container باید تگ GA4 موردنظر را داشته باشد؛
  تنظیمات داخل حساب Google از این مخزن قابل بررسی نیست. بازدیدهای بسیار کوتاه پیش
  از شروع tracking ممکن است ثبت نشوند.
- مسیر فایل لوگوی محلی پیش از ارسال بررسی می‌شود؛ در نبود فایل، لوگوی همراه برنامه
  یا نام مشتری نمایش داده می‌شود. خطای تصویر خارجی هم به همین ترتیب fallback دارد.
  رکوردهای مشتری و فایل‌های آپلودی حذف نشده‌اند.
- دادهٔ تکراری blocks که Home.vue استفاده نمی‌کرد از payload حذف شده است.
- فقط Peyda Regular و SemiBold، متناسب با متن و تیتر هیرو، preload می‌شوند.
  خانواده‌های برند حذف نشده‌اند: در بررسی محلی کل صفحه هنوز هشت فایل فونت مصرف
  می‌کند (چهار Peyda، سه Lahzeh و یک Maneli). هدف سه یا چهار فایل برای کل صفحه
  در این تغییر محقق نشده است.

## نصب بستهٔ اصلاح روی سایت موجود

بستهٔ `dist/cpanel/sizdah-speed-20261125.zip` یک به‌روزرسانی برای همین نسخهٔ پروژه
است؛ وابستگی یا migration جدید ندارد. از فایل‌های مقصد بکاپ بگیرید و فایل‌ها را
روی نصب موجود ادغام کنید. در نصب با پوشه‌های جدا، محتوای `app`، `config` و
`resources` در `sizdah` و محتوای `public/build` در `public_html/build` قرار می‌گیرد.
دارایی‌های جدید را پیش از manifest.json جایگزین کنید و فایل‌های hashed قبلی را
تا پایان بازدیدهای جاری نگه دارید. `.env` و `storage` در بسته نیستند.

پس از آپلود، کش قالب Blade و کش صفحات را پاک کنید. با ترمینال:

```bash
php artisan view:clear
php artisan tinker --execute='\App\Services\Performance\PageCache::flush();'
```

اگر تنظیمات config کش شده‌اند، `php artisan config:clear` هم لازم است. بدون
ترمینال، فایل‌های PHP تولیدشده در `storage/framework/views` و فایل تولیدشدهٔ
`bootstrap/cache/config.php` را پاک کنید و از پنل «عملکرد» کش صفحات را purge کنید.
کش صفحات مهمان از قبل در پروژه وجود دارد و پیش‌فرض آن روشن است؛ تنظیم ذخیره‌شدهٔ
خاموش همچنان اولویت دارد، بنابراین وضعیت آن را در پنل بررسی کنید.

## SSR و سنجش روی هاست

SSR واقعی در `resources/js/ssr.ts` وجود دارد، اما تنظیم آن برای هاست اشتراکی به‌صورت
خودکار روشن نشده است. برای استفاده باید هاست اجرای دائمی Node را پشتیبانی کند،
`npm run build:ssr` ساخته شود، `php artisan inertia:start-ssr` زیر process manager
اجرا شود و `INERTIA_SSR_ENABLED=true` تنظیم شود. روی هاست بدون آن سرویس، نسخهٔ
خواندنی Blade و preloadهای بالا مستقل از SSR کار می‌کنند؛ Blade معادل hydration
واقعی Vue نیست و جایگزینی نمای اولیه توسط Vue همچنان انجام می‌شود.

پس از نصب، Lighthouse موبایل را بدون افزونه و با تنظیمات یکسان تکرار کنید. در
Network باید Home و تصویر مناسب هیرو از HTML اولیه کشف شوند، درخواست لوگوی
ناموجود محلی حذف شود و دانلود مستقیم GA4 در کنار GTM دیده نشود. در بازدید مهمان
دوم، هدر `X-Page-Cache: HIT` را بررسی کنید. TTFB کمتر از ۶۰۰ میلی‌ثانیه،
LCP load delay کمتر از یک ثانیه و TBT کمتر از ۲۰۰ میلی‌ثانیه هدف‌اند؛ تا اندازه‌گیری
روی هاست واقعی تأیید نشده‌اند.

## اعتبارسنجی محلی

بیلد مرورگر، بررسی TypeScript و بیلد SSR موفق بوده‌اند. ۳۵ تست مرتبط عملکرد،
آنالیتیکس و محتوای اولیه با ۲۱۴ assertion پاس شده‌اند. بررسی Chromium در عرض‌های
۴۰۲، ۹۰۰ و ۱۴۴۰ تصویر preload متناسب، صفر خطای JavaScript و صفر تصویر شکسته را
نشان داد. در حالت موبایل لمسی، فایل motion دریافت نشد. آزمون مرورگری جداگانه،
یک‌بار بارگذاری tracking پس از چند تعامل و توقف/شروع/پاک‌سازی انیمیشن خارج/داخل
دید را نیز تأیید کرد.

کل مجموعهٔ تست‌ها سبز نیست: سه تست SectionEditorTest در فایل تغییرنکردهٔ
`app/Filament/Resources/ProjectResource/RelationManagers/SectionsRelationManager.php:136`
به‌علت دریافت array در callback با نوع `?string` خطای TypeError دارند. اجرای گسترده
به حافظهٔ بیشتر از سقف پیش‌فرض ۱۲۸ مگابایت PHP نیاز داشت و با سقف یک گیگابایت
تکمیل شد. این نتایج محلی جای اندازه‌گیری Lighthouse روی هاست را نمی‌گیرند.
